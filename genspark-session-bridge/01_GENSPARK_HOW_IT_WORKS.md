## إجابات أسئلتك واحدة واحدة:

### ❓ "إزاي شات جديد بنفس الرابط بيكمل بحساب آخر؟"
لأن **الكود في GitHub مش في الشات**. أي شات جديد (حتى بحساب Genspark مختلف)
لو اتربط بنفس ريبو GitHub (خصوصاً لو **عام/public**) ➔ الساندبوكس الجديد
بيسحب نفس الملفات ➔ والأيجنت الجديد بيقرأ ملفات السياق
(README / PROGRESS.md / 00_MASTER_RESUME_PROTOCOL.md) ➔ فيبان كأنه "فاكر".
**هو مش فاكر — هو قارئ.** السياق منتقل عبر الملفات، مش عبر الذاكرة.

### ❓ "ليه لما بيخش بنفس الرابط بيعمل رابط منصة جديد؟"
فيه نوعان روابط ولازم تفرّق بينهم:
| الرابط | مثال | عمره |
|---|---|---|
| رابط GitHub | `github.com/number949481-ux/TTTTT` | **دائم** — هو الحقيقة الوحيدة |
| رابط خدمة الساندبوكس | `https://3000-abc123.e2b.dev` | **مؤقت** — نفق مربوط بالساندبوكس الحالي |
كل ساندبوكس جديد = نفق جديد = رابط `e2b.dev` جديد. ده طبيعي 100% ومش مشكلة.
عايز رابط ثابت؟ ➔ Deploy (نشر) للموقع، ساعتها بياخد رابط استضافة دائم.

### ❓ الدليل العملي (حصل معانا حرفياً النهارده):
في الجلسة السابقة بنينا `connect-now-lab/` (بروتوكول CONNECT-CAPSULE + relay.py
+ حادثة INCIDENT-CP0-001). الجلسة دي = ساندبوكس جديد ➔ المجلد ده **غير موجود هنا**
لأنه كان اتعمل له commit محلي في ساندبوكس الجلسة القديمة ولم يُدفع للريبو الرئيسي.
الذاكرة الوحيدة الناجية = سياق المحادثة نفسه + ما وثّقناه. عشان كده المجلد ده اتولد.
