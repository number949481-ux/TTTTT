## 🎯 الهدف
`continue_project.py` (الملف 07) بيكمل مشروع **من رابط بتديهوله يدوياً**.
`gs_link_store.py` بيحل المشكلة المكمّلة: **إزاي المحرك نفسه يفتكر آخر مشروع تلقائياً؟**

## 🧱 شكل الملف `gs_link_store.json`
```json
{
  "default":            ["<PID الأحدث>", "<الأقدم>", "<الأقدم أكتر>"],
  "acc_user@mail.com":  ["<PID>"],
  "_owners":            { "<PID>": "owner@mail.com" },
  "_updated_at":        "2026-08-29T12:00:00+00:00"
}
```
- **المفتاح** = اسم المحادثة المنطقي (`default` أو `--conv`) — وفي الوضع المتوازي = إيميل الحساب
  (كل حساب يكمل سياقه هو، من غير تضارب).
- **القائمة** = آخر 3 PIDs (الأحدث أولاً، `MAX_KEEP=3`)، بدون تكرار.
- **`_owners`** = خريطة PID ➔ إيميل صاحبه (lowercase) — أساس «قفل المالك» تحت.

## ⚙️ الواجهة العامة (API)
| الدالة | ماذا تفعل | ضمانة |
|---|---|---|
| `push_pid(pid, key, owner=None)` | يضيف PID للمقدمة (+يسجل owner لو اتبعت) | يرفض أي نص غير UUID 8-4-4-4-12 (زي `__INVALID_PROJECT__`) ويرجع `False` |
| `get_pid(key)` | الـ PID النشط (الأحدث) أو `None` | تطبيع كامل (lowercase + إزالة المسافات حتى الداخلية) |
| `get_pids(key)` | القائمة كلها (بحد أقصى 3) | القراءة آمنة — JSON تالف = قائمة فاضية بصمت |
| `get_owner(pid)` | إيميل صاحب الـ PID أو `None` | يتسامح مع PID باظ في المدخل (بيطبّعه الأول) |
| `drop_pid(pid, key)` | يشيل PID باظ فيترقّى اللي بعده تلقائياً | يمسح الـ owner بتاعه كمان |

## 🛡️ ضمانات السلامة المدمجة
1. **كتابة ذرية**: `tempfile.mkstemp` + `fsync` + `os.replace` — استحالة ملف نص-مكتوب.
2. **🩹 Self-Heal**: عند أول قراءة بيصلّح الملف كله تلقائياً — PIDs فيها مسافات داخلية
   (زي `9de3ba6b-9bae -4a45-…` اللي كانت بتمنع التكملة فعلياً) بتتنضف، والعناصر
   التالفة نهائياً بتتشال، ويعاد كتابة الملف مرة واحدة.
3. **Thread-safe**: قفل `threading.Lock` حوالين كل كتابة (مهم للوضع المتوازي).
4. **فشل صامت آمن**: أي استثناء في القراءة/الكتابة = سلوك افتراضي نظيف، مفيش crash للمحرك.

## 🔄 دورة الحياة داخل المحركين (01.04 / 02.07)
```
بداية التشغيلة (Config.continue_from_store=True — الافتراضي):
  1. store_key = --conv أو conv_name
  2. _store_pid   = get_pid(store_key)      ← آخر سياق محفوظ
  3. _store_owner = get_owner(_store_pid)   ← مين صاحبه؟

اختيار الحساب (قلب الميزة — «قفل المالك»):
  • لو صاحب السياق متاح في accounts_genspark.json
      ➔ نفس الحساب ➔ send_chat(project_id=PID) ← تكملة مباشرة بدون Fork ✅
  • لو مش متاح (cooldown/محجوز/اتشال)
      ➔ Smart Picker يختار حساب تاني ➔ ensure_public + Fork
      ➔ السياق محفوظ في مشروع جديد بـ PID جديد 🔀

أثناء التشغيل:
  • لو السيرفر رجّع __INVALID_PROJECT__ (مشروع قديم/محذوف)
      ➔ drop_pid(الباظ) ➔ الـ PID اللي بعده يبقى النشط ➔ Auto-Recovery بالـ history

نهاية ناجحة:
  • push_pid(final_pid, key=store_key, owner=إيميل الحساب المرسل)
      ➔ التشغيلة الجاية تعرف تكمل من هنا ومين صاحب السياق

الوضع المتوازي (parallel): نفس الدورة لكن key = إيميل كل حساب.
```
