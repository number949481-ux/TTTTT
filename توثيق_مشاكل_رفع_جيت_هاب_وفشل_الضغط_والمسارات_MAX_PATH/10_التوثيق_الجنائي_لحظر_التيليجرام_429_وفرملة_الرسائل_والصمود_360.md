## 🔬 2. التشخيص الجنائي والسبب الجذري (Root Cause Analysis - 5 Whys)

### أ. العَرَض المرئي (Symptom):
* تجمد واجهة بوت التيليجرام وتوقفه التام عن الاستجابة لأوامر المستخدم أو عرض التحديثات الحية.
* ظهور خطأ في شبكة التيليجرام: `HTTP 429 Too Many Requests: retry after X seconds`.

### ب. شجرة التحقيق الجنائي (The 5 Whys):
1. **لماذا علّق البوت؟**  
   لأن خوادم Telegram API أوقفت استلام الطلبات من التوكن وفرضت حظراً مؤقتاً (Rate Limit).
2. **لماذا فرض تيليجرام حظر الـ 429؟**  
   لأن البوت أرسل طلبات تعديل متتالية (`editMessageText`) لنفس الـ `message_id` في نافذة زمنية تقل عن ثانية واحدة.
3. **لماذا تكررت طلبات التعديل بهذه السرعة الفائقة؟**  
   لأن البوت مر على عدة حسابات متتالية رصيدها منتهٍ أو صفر، وكل عملية فحص واستبعاد لحساب استغرقت أجزاء من الثانية، وكان كود `AccountSelectionLiveTransport.publish` يستدعي تعديل التيليجرام مع كل حساب بلا أي قيد زمني.
4. **لماذا لم ينتظر البوت مهلة فك الحظر ويكمل تلقائياً؟**  
   لأن دالة `_call_telegram_api_json` لم تكن تفحص باراميتر `retry_after` القادم في جسم الاستجابة 429، واعتبرته فشلاً عادياً ورجعت بـ `ok: False`، فدخلت حلقة التحديثات في حالة صمت أو محاولات مكررة أعادت تصفير مؤقت الحظر لدى خوادم تيليجرام.
5. **السبب الجذري النهائي (Root Cause):**  
   غياب صمام فرملة زمني (Throttling Window) لرسائل التخطي السريعة، وعدم وجود صمام ارتداد تلقائي (Auto-Backoff Retry) يحترم توجيهات الـ 429 من تيليجرام.

## 🛠️ 3. الحل المعماري القياسي (The Architectural Invariants)

تنفيذاً لرؤية الباشمهندس مالك المشروع وتوافقاً مع صمامات بُلّة SRE:

### 1️⃣ فرملة الـ 7 ثواني (7.0s Throttling Interval):
* يتم حفظ طابع زمني لآخر تعديل ناجح للرسالة `self.last_publish_time`.
* أحداث التخطي السريعة للحسابات التي رصيدها صفر (`attempt-skipped` / `account-switch`):  
  إذا لم يمر 7.0 ثوانٍ على الأقل منذ آخر تعديل، **يتم تخطي إرسال التعديل إلى تيليجرام**.
* **الشفافية الكاملة:** يستمر التيرمينال ولوج النظام في تسجيل كل خطوة وحساب في الخلفية ثانية بثانية دون أي تأخير.

### 2️⃣ صمام استثناء الأولوية الفوري (Priority Event Bypass):
* عندما يمسك الحساب ويقبل بنجاح (`account-claimed` / `attempt-succeeded` / `continuation-handoff-ready`):  
  **يتم كسر حاجز الـ 7 ثواني فوراً** وإرسال التعديل للتيليجرام في نفس اللحظة ليراها المستخدم لحظياً.

### 3️⃣ صمام الأمان لإعادة المحاولة عند الـ 429 (Auto-Retry on 429):
* إذا رد تيليجرام بـ `HTTP 429`، تستخرج الدالة حقل `parameters.retry_after` (أو تستخدم 3 ثوانٍ افتراضية)، وتدخل في سبات آمن `time.sleep(retry_after + 1)` ثم تعيد المحاولة تلقائياً للرسائل الحيوية، مما يمنع تجمد المحادثة.

### 4️⃣ التوافق المزدوج الكامل (Dual Parity SSOT):
* تطبيق التعديل الجراحي في الملف المرجعي الكبير **`01.33_telegram_gen_bridge.py`** (الأصل) وفي ملف الحزمة المقسم **`bridge_refactor/parts/p04_telegram_api.py`** بالتوازي.
* بقاء ملف **`01.03Genspark_claude-opus-5-code.py`** معزولاً ومحمياً (Hands-Off) لثبوت خلوه من أي تعامل مباشر مع التيليجرام.

```python
class AccountSelectionLiveTransport:
    def __init__(self, chat_id: int | str, project_key: str, project_name: str):
        self.chat_id = chat_id
        self.project_key = str(project_key or "")
        self.project_name = str(project_name or "")
        self.message_id = None
        self.last_text = ""
        self.renderer = AccountSelectionLiveRenderer(project_key=self.project_key, project_name=self.project_name)
        self.sent_handoff_signatures: set[str] = set()
        self.last_publish_time = 0.0  # ⏱️ عداد الفرملة الزمنية ضد حظر تيليجرام

    def publish(self, event: dict) -> bool:
        text = self.renderer.apply(event)
        now = time.time()
        event_type = str(event.get("event") or "").strip()
        is_priority = event_type in ("account-claimed", "attempt-succeeded", "continuation-handoff-ready")
        
        # 🛡️ فرملة الـ 7 ثواني للحسابات السريعة مع كسر فوري للأحداث المفصلية
        if self.message_id and not is_priority and (now - self.last_publish_time < 7.0):
            return True

        send_ok = False
        if self.message_id:
            edited = edit_telegram_message_text(self.chat_id, self.message_id, text)
            if edited.get("ok"):
                self.last_publish_time = now
                self.last_text = text
                send_ok = True
```
